## Preliminary signals (measured, pre-feel-test)

### Bench results

Five warm runs each, startup→first frame in ms, same machine (M-series Mac),
same session. Go measured via compiled binary under a pty (`script`), so the
number reflects binary startup, not `go run` compile time.

| Prototype | 5 runs | 500 rows |
| --- | --- | --- |
| Ink (Node 22 + tsx) | 437, 318, 319, 308, 325 (median ≈ 319) | 345 |
| Ink (Bun 1.4) — bonus | 126, 84, 80, 87, 81 (median ≈ 84) | — |
| OpenTUI (Bun 1.4, 0.5.9) | 38.6, 37.2, 39.7, 40.2, 39.5 (median ≈ 39.5) | 39.0–44.4 |
| Go + Bubble Tea v2 (compiled) | 0, 0, 0, 0, 0 (< 1 ms) | < 1 ms |

Reading: the gap is runtime startup, not rendering. Node+tsx pays ~320 ms of
transpile/startup tax every single invocation; Bun cuts that ~4×; OpenTUI's
native renderer adds little on top of Bun; Go is effectively free. All three
handle 500 rows without measurable degradation. Caveat: OpenTUI's renderer
only speaks to a real pty, so its bench (like the Go one) was taken under a
pty wrapper; Ink's was taken directly.

### CLI pass (same five commands in all three)

Exit-code behavior is identical across all three: 0 on success, 1 on unknown
command and unknown skill. Help is generated by the framework everywhere.

- **Go + Cobra**: richest help (long description, command list, flags), but the
  auto-added `completion` command is noise. Errors: `Error: unknown skill: nope`,
  `Error: unknown command "frobnicate" for "skillctl"`. `toggle` adds a nice
  free touch: `would disable tdd (currently enabled)`.
- **Ink + Commander**: cleanest help of the three; error style
  `skillctl: unknown skill 'nope'` / `error: unknown command 'frobnicate'`.
  The `[ELIFECYCLE]` noise around failures is pnpm, not Commander.
- **OpenTUI + Commander 15**: identical shape to Ink's — Commander was
  deliberately held constant across both TS prototypes. Same error wording
  conventions, same exit codes.

CLI verdict shaping up: Cobra buys structure you don't have to think about
(and pays in generated noise); Commander is lean and does everything the spec
asked. Both TS prototypes' CLI code (128/146 lines) vs Go's 260 — but Cobra's
includes more behavior for free (completions, per-command help).

## Ink + TypeScript

Build friction and API notes: see [`ink/BUILD-NOTES.md`](ink/BUILD-NOTES.md).
Highlights:

- pnpm 11 build-approval archaeology (`allowBuilds` map in
  pnpm-workspace.yaml) cost real time and blocks `pnpm exec` until resolved
- tsx's CLI pipes the child's stdio — silently disables `useInput`; must run
  `node --import tsx` for any scripted TTY work
- Ink treats one stdin chunk as one keypress (bursts arrive as one string)
- `--bench` for free via `performance.now()` from process start, unmounting
  from the first-frame effect exits cleanly

Startup: ~319 ms median on Node/tsx; ~84 ms under Bun. Filter/staging/apply
all verified under a fake TTY; 40-key held-`j` burst produced 42 frames, no
dropped renders.

## OpenTUI + TypeScript

Build friction and API notes: see
[`opentui/BUILD-NOTES.md`](opentui/BUILD-NOTES.md). Highlights:

- The build stalled the first time on a real bug, not slowness: a `<span>`
  mounted directly in a `<box>` throws at render, and the ErrorBoundary masks
  the crash as a freeze. That constraint (inline styled text only inside
  `text`) is the sharpest 0.5.9 edge found
- Key normalization is inconsistent: ESC arrives as raw `"\x1b"` sequence while
  arrows arrive as names
- OpenTUI's `<input>` broke on every parent re-render; the filter line is
  hand-rolled over `useKeyboard` (works, but you're building form widgets)
- `createTestRenderer` + `captureCharFrame` test utils are genuinely excellent
  — 31 deterministic checks against captured character frames

Startup: ~39 ms median on Bun — 8× faster than Ink-on-Node, with a native
renderer. Hand-rolled window scroll handled 500 rows fine. Mouse support
exists and is tempting (noted, not built).

## Go + Bubble Tea v2

Build friction and API notes: see
[`go-tui/BUILD-NOTES.md`](go-tui/BUILD-NOTES.md). Highlights:

- The gotcha of the whole exercise: under the Kitty protocol (v2 default),
  `KeyPressMsg.String()` for space is `"space"`, not `" "` — a `case " "`
  silently never fires and only a scripted pty test catches it
- Alt-screen moved to a field on the returned `tea.View` in v2; the plan's
  sketch otherwise matched the real API closely
- Cancellation of the 300 ms apply needed a generation counter (~6 lines) —
  in TS this is an AbortController you'd probably forget to wire
- 743 lines, the most of the three, mostly return-value plumbing and
  hand-rolled row truncation; Cobra's tree declared itself in ~40 lines with
  all behavior free

Startup: < 1 ms from the compiled binary — no cold-start cost at all. 500 rows
imperceptible.

## How to run each prototype

```sh
# Ink (TUI + CLI)
pnpm --dir prototypes/ink dev
pnpm --dir prototypes/ink cli -- list

# OpenTUI (TUI + CLI) — Bun required
cd prototypes/opentui && bun run dev
cd prototypes/opentui && bun src/cli.ts list

# Go (TUI + CLI)
cd prototypes/go-tui && go run . tui
cd prototypes/go-tui && go run . list
```

All three accept `--rows N` (stress fixture) and the TUIs accept `--bench`.
